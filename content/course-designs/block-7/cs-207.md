## CS-207 — Advanced Graph Algorithms & Networks

**1 credit**

### Working description

Students return to graphs with traversal foundations in hand: BFS, DFS, adjacency representations, and connected components were established in CS-112 (B4). This course applies that vocabulary to hard optimization problems on weighted networks — the shift from "exploring a graph" to "finding the best something in a graph."

**Advanced optimization algorithms.** Shortest path on weighted graphs: Dijkstra's algorithm (correctness argument, not just recipe — why the greedy choice works on non-negative weights); A\* as a heuristic extension using geospatial distance as the guiding intuition (connects to greedy strategies from CS-112). Minimum spanning trees: Kruskal's and Prim's algorithms as two different greedy strategies for the same problem. Geospatial context grounds all three: routing on road networks, infrastructure planning under cost constraints, coverage optimization.

**Graphs as the terminal data-structures pass.** The data-structures spiral concludes here: primitive values (B1) → sequences (B3) → hierarchies and hash tables (B4) → arbitrary relationships (B4, first pass) → optimization on weighted relationships (B7, this course). Each step generalized the previous; this step shows why graphs are the most expressive structure and what that expressiveness costs in algorithmic difficulty.

**Computational Models pass.** A brief see-and-explore example of a logic/constraint model (Prolog-style facts and rules, or a small constraint problem solved declaratively) — connects to MATH-101 predicate logic, SQL's declarative character, and the observation that some problems are better specified as constraints than as algorithms.

Signature assessment: Design Review begins in this block (see below).

## Competency Assessments

**Signature assessment anchored here:** Design Review — students present a system design to a panel of peers and faculty and defend their choices under critique (evidence generated: Design Software Systems; Develop Abstractions; Evaluate Algorithmic Solutions; Communicate Technical Information; Evaluate Ethical Implications).

| Assessment type | This pass | Competencies evidenced |
|---|---|---|
| Code Archaeology | Integrated system archaeology — trace behavior across multiple components and data stores | Analyze Computational Systems; Maintain Software Systems |
| Design Brief | Choose and defend the right abstraction tier for the problem (graph vs. relational vs. document) | Develop Abstractions; Design Software Systems |
| Formal Analysis | Correctness argument for a graph algorithm; evaluate a peer's formal argument in Design Review | Apply Formal Reasoning |
| Algorithm Evaluation Task | Multi-objective tradeoff — Dijkstra vs. A\*, data store selection with competing constraints | Evaluate Algorithmic Solutions; Represent Information |
| Implementation Task | Feature implementation in a collaborative codebase — professional workflows, team-defined specs | Implement Software Solutions |
| Usability Evaluation | Design Review — peers evaluate each other's system designs for human-centeredness and usability fit | Design Human-Centered Solutions |
| Technical Explanation Task | Design Review presentation — defend technical decisions to critical peers and faculty | Communicate Technical Information |
