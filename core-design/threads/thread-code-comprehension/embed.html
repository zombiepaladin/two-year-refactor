Code Comprehension

Working draft for faculty review. A spiral deepens through escalating passes across the two-year core. This is the spiral; one of eight spirals (with three lenses and one bounded practice — twelve threads total, plus two cross-cutting norms).

In one line: Understanding programs — your own and others’ — from ‘make it work’ to ‘defend it under scrutiny.’

Character

The lens shifts each pass rather than just raising difficulty: produce → understand others’ → organize → reason about → defend.

Passes across the two years

Course What’s new at this pass
CIS 116 (Y1 Fall) — Introduction to Programming Write small correct programs across the paradigms it introduces (imperative and functional, with the same widgets carried forward from the original design); “make it work.” Also a first, informal comprehension touch in the same course — SLO 4 is explicitly “read, interpret, and modify existing computer programs,” ahead of CIS 200’s formal Code Archaeology pass.
CIS 200 (Y1 Spring) — Programming Fundamentals Read others’ code, explain unfamiliar behavior — the thread’s signature “Code Archaeology” assessment; “understand before judging.” Encapsulation/abstraction as comprehension tools (tied to the course’s OOP introduction) and functional-pattern formalization (map/filter/reduce): organize so intent is legible.
CIS 301 (Y2 Fall) — Logical Foundations of Programming Reason systematically about whether code does what it should — this course’s own confirmed purpose is deepening propositional/predicate logic into program verification, a natural extension of comprehension into formal reasoning.
CIS 400 (Y2 Spring) — capstone of the core Defend your understanding and choices under scrutiny — a live walkthrough / architecture defense is the course’s actual assessment mechanism, not spec-compliance alone.
