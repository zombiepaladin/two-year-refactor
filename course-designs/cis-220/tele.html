CIS 220 - Platform Programming

Potential new course to be developed. Initial offering would focus on programs written for the web browser. Serves as a vehicle for providing event-driven programming and operating systems coverage for progammer-specific needs. Serves as part of a three-course progression, CIS 120 → CIS 220 → CIS 320. May need to be merged with CIS 320 to minimize staffing requirements.

Course Description

Programming against an interactive computing platform’s execution and event model — how the platform schedules code, isolates security boundaries, and supports concurrent and asynchronous behavior. Sections focus on a specific platform (e.g. web, mobile, desktop); consult the section syllabus for the platform and tools used. (Proposed catalog description, per resources/reference/degree-maps/cs.md.)

Credit Hours

1 credit (per resources/reference/degree-maps/cs.md)

Course Overview

Reframed 2026-07-15 — generic catalog identity, specific curriculum design. The catalog name/description/outcomes are deliberately platform-agnostic, so this course number can host different platform sections (Web, Mobile, Desktop) in the future without a new catalog entry each time. The two-year core runs the Web section: a deeper dive into JavaScript, event-driven programming, and DOM manipulation, building on CIS 120’s HTML/CSS/JS seed. Carries the “browser as a mini-OS” framing (event loop schedules code, origins as a security/process boundary, web workers as concurrent work, postMessage as IPC) — the confirmed required-content fix for the ABET “operating systems” gap, at the exposure level the criterion actually asks for. Also serves as real prerequisite depth for CIS 320. See resources/reference/degree-maps/cs.md’s CIS 220 entry for full detail.

Course Goals and Learning Outcomes

Proposed catalog learning outcomes (generic, per cs.md): explain how an interactive platform schedules and executes code (event-loop/message-queue model); reason about the platform’s security/isolation boundaries; write programs that respond to asynchronous events and coordinate concurrent work using platform-appropriate mechanisms; manipulate a platform’s structured content/state model programmatically. Web-section-specific outcomes not yet drafted.

Course Prerequisites

Prerequisite: CIS 120 (per resources/reference/degree-maps/cs.md).

Proposed Changes

  • Multi-source integration: multi-objective tradeoff reasoning (Optimization lens) and re-identification risk from combined datasets (Trustworthy Computing lens). Both lenses describe this course (paired with CIS 320) as carrying a scenario where multiple external data sources are combined — raising both a speed/completeness/privacy tradeoff and a re-identification privacy question. This scenario has no confirmed course to carry it; it is not in this course’s real drafted outcomes, which describe a single platform’s event-loop/security-isolation model, not multi-source integration. The confirmed 2026-07-15 “integrate” content for the CIS 220/CIS 320 pairing is “APIs as structural boundaries” (a single provided API), not combining multiple sources. Logged here as a proposed addition, not yet built — needs a course-designer/faculty decision on whether the multi-source scenario is reintroduced (and where) or the lenses are rescoped to the confirmed single-API-boundary content instead.
