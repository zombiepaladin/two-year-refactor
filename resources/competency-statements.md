
# Cybersecurity

* Students should be able to operationalize the concept of defensive programming

* Students should be able to identify and avoid common cybersecurity issues, e.g., buffer (stack and heap) overflows, format strings, use-after-free, etc.

* Students should be able to identify situations where untrusted data is executed as code by a program, e.g., SQL injection, strings passed into "system()" calls, etc. (really, this is a common security issue like above, but it's complex enough to serve its own bullet)

* Students should be able to identify and sanitize untrusted inputs using best practices, e.g., allow-listing instead of block-listing

* Students should be able to implement confidential and authenticated network communication using TLS (using libraries)

* Students should be able to appropriately integrating common cybersecurity controls into software they develop, e.g., authentication, authorization, integrity, confidentiality, auditing, etc. (using shared libraries or language runtime or operating system-provided methods)

* Students should be able to define trust boundaries in multi-component and/or distributed applications (in terms of planning/design as well as evaluation)

* Students should be familiar with the use of basic security controls such as encryption, message authentication codes, signatures, authenticated encryption, etc.
